# QWind: QAOA for Wind Farm Turbine Selection

**Theme:** Quantum Impact · **Status:** Hackathon submission (Qollab)

Wind turbines steal wind from each other: every turbine leaves a slower, turbulent "wake" behind it, and any turbine standing in that wake produces less energy. So *where* you place turbines matters.

**QWind** picks the best *K* sites out of *N* candidates, using a quantum algorithm (QAOA, built with Qiskit), and compares it honestly against classical methods. With real farms it is a **selection (curtailment) problem**: choose which *K* of the existing turbine positions to keep operating. It is not layout design.

**Honest expectation:** at the sizes a simulator can handle, classical methods solve this exactly in milliseconds. **We do not claim a quantum advantage.** The goal is to measure how close QAOA gets to the best layout, how that changes with circuit depth, and where it starts to break down.

**Try it:** click **Run your code** on this page (built-in simulator). Source code, tests and experiments: https://github.com/agustindiazcano/qwind-qaoa-windfarm

**How to read this**
- The reference point is the *uniform distribution over feasible layouts*, not "1": QAOA's approximation ratios are well below 1, and the absolute values are in the tables.
- The penalty formulation does not beat the uniform baseline consistently for any penalty weight tested (see the ranges above). The constraint-preserving ansatz (XY mixer + Dicke start) beats the uniform baseline on the approximation ratio over feasible layouts in every instance reported here, at p = 1 to 3; on P(optimal) it does so in most instances but not all (counts in the table).
- Classical methods solve these instances exactly or nearly so (simulated annealing reaches gap 0 in every dataset; greedy search misses by a small margin on two), with evaluation budgets that are not matched to QAOA's. The best layout sampled from QAOA (1000 shots) is on average not better than the one found by simulated annealing, and its mean gap is above zero on the larger datasets. **We do not claim a quantum advantage, a speedup, or energy or cost savings.**
- Penmanshiel, Kelmarsh (3 instances each) and `real_penmanshiel_sub10` are too small for a mean and interval: `results/results_tables.md` lists them instance by instance. Datasets are never averaged together.
- At N = 14 (`real_penmanshiel`) the probability of sampling the optimal layout is tiny in absolute terms for both QAOA and the uniform baseline; what improves is the distribution over feasible layouts.
- One run per instance, a single simulator, instances of at most 14 cells, and results from one environment (Python 3.12.15 in GitHub Actions; the Qollab Run uses Python 3.14.2 and gives slightly different values for the same seed). We do not claim reproducibility across environments.

## Technical details

### The problem
Choosing *K* turbine sites out of *N* candidates is a combinatorial optimization problem: the number of layouts grows as C(N, K). We encode the wake losses as a **QUBO** with a cardinality constraint:

```
E(x) = sum_i h_i x_i + sum_{i<j} J_ij x_i x_j + lam * (sum_i x_i - K)^2

x_i  = 1 if a turbine is placed at site i
h_i  = -P0   (negative isolated-turbine power)
J_ij = pairwise wake loss between sites i and j (wind-rose weighted)
lam  = penalty weight for the "exactly K turbines" constraint
```

### Physical model
- Jensen/Park top-hat wake model: the velocity deficit decays with downwind distance inside an expanding wake cone.
- A wind rose (direction, frequency, speed) weights the losses; power scales with wind speed cubed.
- **Approximation:** losses are pairwise additive. A full multi-wake superposition is not pairwise, so this is a simplification (documented in `docs/model.md`).

### Quantum part
- QAOA with depth *p* = 1, 2, 3: diagonal cost layer plus RX mixer, built in Qiskit.
- The Hamiltonian is built by hand as a `SparsePauliOp` (Ising mapping `x = (1 - Z) / 2`, qubit *i* = bit *i* of the state index).
- Constraint-preserving variant: XY mixer and Dicke initial state, in the line of Hadfield et al. [1] and Bärtschi and Eidenbenz [2]; the Dicke state is built with Qiskit's `StatePreparation`, not with their circuit. Parameter ramp inspired by Sack and Serbyn [3] (their paper studies MaxCut; ours is not a replication).
- Expectation values with `StatevectorEstimator`, classical optimization with `scipy.optimize` (COBYLA) and multiple seeded restarts, final sampling with `StatevectorSampler`.

### How the circuit is simulated
We simulate the full QAOA circuit in Qiskit and compare it against classical methods. `StatevectorEstimator` and `StatevectorSampler` compute the exact expectation values and the exact output distribution of the circuit on the CPU, so the optimization has no shot noise. We do **not** call `backend.run` inside the optimization loop (project rule): every backend call goes through the platform's job handling, and an optimization needs hundreds of evaluations. We have not benchmarked that route ourselves, so we state it as a design choice and not as a measurement. Nothing runs on quantum hardware and no advantage is claimed.

### What this adds beyond running QAOA
- A comparative benchmark with controls: uniform sampling over feasible layouts and random feasible sampling with the same number of shots, next to exact, simulated annealing and greedy search.
- A constraint-preserving variant (XY mixer with a Dicke start state) against the penalty formulation.
- Real data: operating-farm turbine positions and measured wind roses, plus ERA5 roses as a secondary dataset (sources and licenses in `docs/DATA.md`). It is a selection problem (choose *K* of the existing turbine positions to keep operating), not layout design.

### Classical baselines
- Exact enumeration (ground truth)
- Simulated annealing
- Greedy search with local swaps

### What we measure
- Gap to the optimal layout
- Probability that QAOA samples the optimal layout
- Probability mass on feasible layouts (exactly *K* turbines)
- Effect of circuit depth (*p* = 1, 2, 3)
- Instance size limits (qubits versus runtime)

### Run environment (Qollab)
- Python 3.14 on Qollab (results produced with Python 3.12 in GitHub Actions), Qiskit 2.5.2, NumPy, SciPy on the built-in simulator.
- The live Run uses a small instance: default N = 8, recommended up to 10 cells, hard limit 12 (N = 14 took 42.8 s there, over the 30 s budget). Larger instances, including the full 14-turbine Penmanshiel farm, are computed offline and their stored results are included.

## How to run

**On Qollab:** click **Run your code** with the built-in simulator selected. The default Run (N = 8 cells, K = 3 turbines, QAOA depth p = 2, seed 0) prints one comparison table of exact enumeration, simulated annealing, greedy search and QAOA (XY mixer + Dicke start), followed by a detail block that compares QAOA with the uniform-over-feasible baseline.

**Locally:**
```
pip install -r qollab/requirements.txt pytest
python qollab/main.py            # the same Run as on Qollab
python -m pytest                 # tests (add -m "not heavy" to skip the slowest ones)
```

**Offline experiments** (fixed protocol `qwind-v1`, never retuned): `python experiments/run_all.py --dataset <name> --jobs 4`, then `python experiments/run_all.py --merge`. The heavy runs were executed with the manual GitHub Actions workflow `run-experiments.yml`. Tables: `python scripts/make_results_tables.py --readme README.md`.

## Limitations

- Simplified wake model: Jensen losses that are pairwise additive (a full multi-wake superposition is not pairwise); mean wind speed is stored in the data but not used by the model yet.
- Small instances only (at most 14 cells, exact statevector simulation); the live Run is limited to 12.
- Simulation only on the CPU (Qiskit statevector primitives); no real quantum hardware and no noise.
- Real here means real turbine positions and a measured or reanalysis wind rose, not a validated farm model: the nacelle anemometer sees upwind wakes, one year (2019) per farm, and the farm layouts were not designed for this objective.
- Few instances for the real farms (3 each); no statistical claim beyond this benchmark.
- No quantum advantage is claimed.
